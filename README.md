# 总控制台

运营任务、素材、剪辑和发文交接的本地总控制台。先确认流程和纯前端 Demo，再按计划接入单机 MVP，最后支持局域网分工。

- [项目规范](项目规范.md)：范围、只读数据边界和开发顺序。
- [计划索引](plan/README.md)：当前唯一计划、依赖和验收状态。

## 本地任务工作台

双击 `启动总控制台.bat`，或运行：

```powershell
python tools/local_server.py
```

打开 <http://127.0.0.1:8861/>。服务只绑定本机，运行状态、只读来源快照和隔离准备副本保存到被Git忽略的`runtime/`。使用Python 3.10及以上，不需要安装第三方包。停止按Ctrl+C；端口占用可指定`--port 8862`，不会结束已有进程。`--runtime-dir`可指定另一个独立数据目录。

“每日选品”采用已选A布局：先选账号，在商品列表加入持久草稿，核对固定16列后追加任务，可下载当日XLSX。需先核对账号F范围、UID和合作码，并确认无年份商品日期的来源年份。详见[每日选品接口与顺序](docs/每日选品接口-006A3.md)。原导入和交接入口继续保留。

1. 点击“导入本地副本”，选择原格式任务表xlsx，预览精确16列和逐行问题后确认导入。
2. 导入人工取得的账号副本，按A:F读取身份和F允许品类，确认工作表、表头行及完整性。
3. 导入完整商品分类副本，逐Sheet选择ID列和类别列，或使用有分类名称的Sheet作为来源；商品标题不构成分类证据。
4. 在“数据快照”维护显式类别别名。缺失、冲突、不匹配、问题行及重复候选会显示阻塞原因。
5. 任务详情可保存独立备注和重复行核对；重启后任务UUID、来源证据和记录保留。M/N只表示来源有回执，未人工核验。

任务表原文件不会被修改。再次导入同文件和解析选项不会创建重复任务；改动文件后会保留新的来源批次，疑似同日重复任务需核对。

在“素材交接”选择同账号任务，准备独立工作表。配置原素材软件已运行实例的本机端口和实际 `material.db` 路径后，点击“送原软件预览（不启动）”。随后在原软件人工建任务、搜索、预览勾选与确认输出，再回总控只读回收报告和文件摘要。软件报告完成还需要人工复核素材内容，才允许下一阶段交接。失败可登记重试，回原软件处理失败行；总控不会自动采集、下载或删除旧文件。

素材接口依据本机r2源码核对，仅发送预览与只读结果回收。缺行映射、缺持久作业报告、超过100条候选或报告/目录/文件不一致时明确阻塞。

在“剪辑交接”选择同账号、素材已人工复核的任务，生成VideoClean专属工作表、独立素材Root与报告目录。原GUI手工选入本包路径，核对产量、实际程序/版本、正式词表启用、账号装饰、完整ID命名及变速开关；**先保存总控GUI核对记录，再回原GUI人工点开始**。完成后只读回收汇总、逐行报告、L日志及成片，普通/变速各自观看核验后取得对应交接资格。缺变速不会把普通完成抹掉，也不会冒充抖音所需变速完成。总控不启动剪辑程序，原始表和素材不改。发文接入仍按007实施。

## 虚构界面 Demo

双击 `启动Demo.bat`，或在本目录执行：

```powershell
python tools/preview_server.py
```

打开 <http://127.0.0.1:8860/?workspace=demo>。页面只有虚构数据与模拟操作，服务仅绑定本机。停止时按 Ctrl+C。端口占用时可用 `python tools/preview_server.py --port 8862`，不会结束已有进程。本地任务服务页面也可通过“工作空间”选择“虚构演示”，演示数据不写入本机数据库。

网页包含任务进度、原表16列、数据快照、五槽发文交接、主机规划和两张可交互设计图。右上角切换场景可检查品类门禁、成片缺失、失败重试和六账号分批。

## 日常使用

公司电脑使用完整Windows便携包：解压后双击“启动总控制台.cmd”，无需安装Python、Node.js或运行依赖；详见[便携版说明](docs/使用说明-便携版.md)。仓库里的BAT、虚拟环境和测试命令面向开发，不是公司交付包。便携包不含真实账号与业务数据，data在首次运行时创建。

007已按2026-10-16确认方案扩展单机自动发文：`/publish.html`支持账号端口绑定、确认模板、逐批启动、逐视频状态、精确计划关停与集中日志。先完成原流程的成片核验；启动批次会真实提交到平台，准备/预览不执行。真实平台兼容性仍待公司机器验收。

安装环境、接口、暂停/停止及结果不明处理见[自动发文使用说明](docs/发文执行接口与使用-007.md)；旧版缺陷与技术选型见[重构记录](docs/发文重构与旧版缺陷-007.md)。在线只读、原16列与J含义保持不变，008暂缓。

完整单机测试入口为`npm run test:single-machine`，或`python -B tools/run_single_machine_checks.py`。仅用虚构数据和独立临时服务，不操作正式工作区；测试报告保存在被Git忽略的test-results。依赖设置、逐模块结果及人工实机验证边界见[单机自动化完整验收](docs/单机自动化完整验收-007.md)。
