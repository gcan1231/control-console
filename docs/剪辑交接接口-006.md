## 使用顺序

1. 只选素材已人工复核、当前类别证据通过且无M/N发布回执的任务，每包一个账号、1—100个不同任务，同商品重复不并包。
2. 总控生成`runtime/editing/<包ID>/Sheet1.xlsx`及独立素材Root、报告目录。只复制005已确认素材，逐文件核对原摘要，复制时再验证摘要。账号/完整ID不截断；超过VideoClean安全名称80字符范围或非法目录名阻塞，不静默改名。
3. 工作表唯一Sheet1，固定A:P原16字段/J/完整ID。新工作副本仅清空L旧日志，来源L保留；内部映射、路径、确认与状态不写入业务列。
4. 在原GUI选本包工作表、素材Root和报告目录，核对正式有效词表、账号装饰、产量1—200、完整ID命名、变速开关。回总控保存实际GUI设置记录，**再到原GUI手工点开始**。总控按钮只保存记录，不执行剪辑。
5. 等原GUI保存完成后回收。需要本包汇总JSON、每行详细JSON和保存过的工作副本L；原始来源不读取为执行结果。
6. 普通/变速分别显示「报告与文件一致，待观看复核」。每一类单独明确勾选逐条观看内容/账号/商品归属并写记录，才取得对应发布目标的ready资格。006不实施发文。

装饰方案字段是操作人对原GUI实际方案的核对说明；原软件无统一的「无装饰」内部名称，账号专用方案还会自动命名。总控保留详细报告scheme实际对象供复核，不能仅凭名称推导装饰是否正确。

## 回收门禁

- 原GUI记录绑定正式词表和程序文件摘要。文件变化须重新核对；报告generated不得早于本次确认，JSON文件mtime也必须不早于确认纳秒时间，避免同秒旧报告混用。
- 汇总task_table/material_root/export_dir/rules_file必须精确属于本包；报告settings的实际产量、ID模式、batch_freeze须符合人工记录。
- 汇总及行报告rules_info必须checked=true、exists=true、effective_term_count为正整数、parse_error_count=0、source和file_sha256匹配本次词表。跳过禁词、空词表或解析错误不得放行。
- 逐行账号、抖音账号、完整商品ID、行号、商品目录及write_ok必须对应。工作副本除L外15列不得变动；L必须已保存且等于汇总行status。日志文字不能单独证明成功。
- 普通results数量、done/total和人工产量一致；槽号/idx正整数且唯一，来源component_decisions必须指向本包输入，不接受其他账号材料。
- 变速freeze需逐行与汇总行均成功，精确指向相应变速目录；普通/变速分别检查，不以普通完成冒充变速完成。
- 输出记录须有正有限duration及精确`[字节数,mtime_ns]`；实际文件为非空可识别MP4，摘要与报告content_sha256（若提供）一致。目录直接MP4必须恰好对应清单，排除旧片、原素材、其他账号和子目录。
- 这是容器头、文件身份、摘要与软件报告一致性检查，未调用视频解码器；人工观看复核承担实际内容/播放质量核验。软件metadata不能替代人工观看。

回收后再次核验会重新检查输入、词表/程序文件、原报告摘要及输出摘要。报告或文件变化需重新回收，不沿用旧确认。回收完全相同证据保留人工复核；变化或失败撤销对应ready。普通可独立ready；变速缺失仍阻止抖音交接。

原始汇总/逐行JSON字节及内部结果快照独立保存，审计带路径和SHA，可追溯失败前证据。失败重试只登记原GUI补跑说明，复用原包/工作表/输入，不覆盖运行工作副本、不删除历史文件、不启动软件。重复登记同记录幂等。
