# 五槽发文与本机MVP

2026-10-16补充：本文描述保留的旧人工交接路径。用户确认的新自动执行路径见[发文执行接口与使用](发文执行接口与使用-007.md)。两种方式同包互斥，不能先自动执行再交旧软件重发。

发文工作台入口`/publish.html`。原工作台“发文交接”提供独立入口，选品、素材、剪辑与日志原入口保留。页面只通过PublishingProvider访问本机服务，不调用按键脚本、注册插件或操纵业务窗口。

## 操作顺序

1. 先在原流程完成素材确认、剪辑报告回收及成片观看复核。抖音要求变速成片ready，千川要求普通成片ready，双目标要求两种都ready；仅目录有视频不放行。
2. 选择目标和任务，显式填写每个账号的实际端口。J列显示并原样保留，不用于端口自动赋值。不同账号不能共用端口。页面每页50任务，一次选择最多100任务；后台最多500。
3. 准备交接包。后台再次验证任务品类、剪辑报告、视频大小/mtime/哈希与直接MP4清单，复制已核验视频至本包公共videoRoot，保留原视频。
4. 按包内批次在原软件配置五个槽：每槽一个账号、自己的Sheet1工作表与实际端口，共用本包视频根。空槽不生成工作表。超过5账号分下一批，按原任务首次出现账号顺序排列。
5. 核对后“记录人工交接”，再由操作者在原软件人工启动。总控只记录交接，不执行发文。双目标需由操作者在原软件分别选对任务方式。
6. 停止本批，保存并关闭全部槽工作表后，明确确认回收。M“已发布”、N“计划已发布”只是软件回执；缺失/其他文本显示结果未知，不自动重发。
7. 实际查看业务结果，再按任务记录独立人工核验。未知结论可以补充为通过/失败，旧结论保留历史；已通过/失败不允许静默覆盖。重复同结论同说明幂等，不新增发文尝试。

## 隔离与完整性

每包使用独占UUID目录、公共media、每批slot-1.xlsx至slot-5.xlsx及内部manifest。目录形态遵循固定契约：videoRoot/账号/完整商品ID/成片/*.mp4供千川，成片/变速/*.mp4供抖音。只统计相应目录直接MP4，普通和变速名单分别核实。创建失败仅回滚本次自建目录及数据库事务，不清理已有包、原软件目录或视频。

每个Sheet1固定A:P16列，账号内原行顺序保留，无中间空行，长ID文本、J提示、A:L及O:P原值保留。额外运行状态、端口、任务ID、原行映射和文件清单仅存内部元数据。来源已有M/N执行回执阻止新准备；交接前副本M/N已有内容也阻止当新包交接。

回收只读本包已关闭/保存的工作副本，严格核对表头、单工作表、连续行数/顺序、非M/N字段及视频副本身份；拒绝公式、合并、额外非空业务列、路径/视频/清单篡改。全包检查通过才原子记录回执快照。已回收回执改变会阻止覆盖，需人工处理；不会清空M/N再重发。原任务业务列、源表和在线文档不写回。

当前每任务仅一个发文包尝试。相同配置且证据不变的重复准备复用原包；重叠任务、改变模式或端口另建尝试均阻止，包括失败/未知。首版没有自动重试或人工重建尝试按钮，后续更改需独立规则。未知仍可核验，不等于已完成发布。

## 状态与接口

任务分别保存prepared、handed_off、reported、unknown、verified、failed。包状态prepared、handed_off、collected；全部人工通过才verified，全部有终态而含失败为reviewed；仍含unknown继续collected。包的“核验记录齐全”不表示全部发布成功。

| 方法 | 路径 | 请求/返回 |
|---|---|---|
| GET | `/api/publishing/state` | publishingPackages、publishingTasks及含editing资格的原任务列表 |
| POST | `/api/publishing/prepare` | taskIds、mode（douyin/qianchuan/both）、ports（账号ID到实际整数端口）；返回package/reused |
| POST | `/api/publishing/handoff` | packageId、confirmed:true；仅记录人工交接 |
| POST | `/api/publishing/collect` | packageId、confirmedClosed:true；只读回收软件M/N |
| POST | `/api/publishing/verify` | packageId、taskId、result（verified/failed/unknown）、note、confirmed:true |

POST沿用本机Host、Origin、token校验，不提供执行软件或自动重发接口。新增publishing_packages、publishing_tasks保存独立记录；日志仍由006B独立数据库保存，不用于判定业务成功。

## MVP验收边界

工程验证以虚构任务、成片和模拟软件写回为准；六账号已验证分两批、固定表头、J/长ID、普通/变速门禁、报告与人工结果隔离。真实日常业务需操作者在现有GUI完成并核验；没有以测试替代真实发文。006B剪辑日志等待文件与发文EXE日志路径仍是已披露运行验证待办，局域网008尚未开始。
