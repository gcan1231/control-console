# 007 Windows便携包构建与验收

## 构建方式

正式交付采用完整目录ZIP：私有Python运行时、标准库与DLL、固定版本依赖、前端页面和必要服务代码一起分发。使用`._pth`显式指定包内标准库、依赖和app，关闭用户site与系统Python配置回退；主服务和独立账号worker均使用包内python.exe。Playwright自带Node驱动，不需要用户安装Node或下载Chromium；发布仍连接公司现有账号Chrome。

隔离搜索路径和随应用提供第三方依赖的做法参考[Python Windows嵌入式分发说明](https://docs.python.org/3/using/windows.html#the-embeddable-package)。本构建从构建机已安装的匹配Windows x64 CPython组装私有运行时，非拷贝虚拟环境启动器，不在目标机安装软件。

构建机使用项目虚拟环境安装`requirements-runtime.txt`固定版本后执行：

```powershell
.\.venv\Scripts\python.exe -B tools/build_portable.py --output dist/ControlConsole-0.2.0-win-x64
```

构建仅发生在开发机。输出目录须不存在且位于本仓库dist内，脚本不覆盖旧包。输出目录、同名ZIP和ZIP的SHA256文件均不提交Git。包内package-manifest.json记录构建源码提交、工作树是否有修改、Python/依赖版本和逐文件哈希。`Start.cmd --check`离线检查文件与内置驱动，不启动或连接浏览器。

代码与页面按Git跟踪清单及明确工具白名单收录；不复制runtime、.venv、测试数据、来源表格、视频、数据库、日志、真实配置或Chrome profile。许可证保留。首次运行才在包旁创建data，数据与代码分开，更新前备份data。

## 验收区分

便携检查脚本`tests/portable_package_check.py`对ZIP解压副本运行，清空PATH中的开发工具并设置无效PYTHONHOME/PYTHONPATH与Playwright驱动环境，验证运行时确实来自包内。覆盖中文空格路径、完整性检查、本地页面和模块、重启持久化、独立worker及缺组件提示，数据全部虚构。

上述是在本开发机进行的环境隔离检查，不等同于纯净Windows虚拟机或公司电脑实测。纯净Windows 10/11 x64、公司安全策略、实际Chrome及真实平台链路须另行记录。系统中文OCR缺失时保留可读提示和表格文本粘贴方式，不把该能力记为识别成功。

实际本轮结果在检查完成后记录于下方。使用方式见[便携版说明](使用说明-便携版.md)，依赖边界见[依赖盘点](零环境依赖盘点-007.md)。
