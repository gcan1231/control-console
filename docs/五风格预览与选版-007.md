# 007 五种风格预览与选版

2026-10-16。用户要求先制作五种不同风格，以组件样板和关键页选版。本次仅新增独立前端预览，选定后再统一正式界面、实施独立阶段接入。现有业务页面、运行数据库和公司文件未改。

## 预览入口

- 本地服务：`http://127.0.0.1:8861/theme-preview.html`。支持`?theme=A&view=selection`定位主题与页面。
- 离线交付：运行`python -B tools/export_theme_preview.py`生成`dist/总控制台-五种风格预览.html`。复制完整单个HTML到公司电脑，双击即可使用，不需要运行时、依赖或服务。该文件只预览，不提供正式业务执行。
- 顶部切换A—E，左侧切换组件样板、每日选品、软件识别、外部成果接入。主题切换保留当前账号、搜索、筛选和草稿；刷新恢复虚构初始数据。

这是本项目对上述设计方式的适配，不是官方主题或官方组件套件；不引入其React、Bootstrap或网络字体。主题颜色采用背景、文字、边框、交互状态成套变量，参考[shadcn主题规范](https://ui.shadcn.com/docs/theming)和[Ant色彩规范](https://ant.design/docs/spec/colors/)。正文与ID分别至少14px/12px；业务表格密度以既有规范为准。

使用本机ui-ux-pro-max查询布局与状态规则，frontend-design指导层级与文案，web-design-guidelines检查表单、焦点及反馈。首次设计系统查询误配营销入口，不采用其hero、销售CTA等建议；收窄到data-dense-dashboard风格域后，采用紧凑表格、可见焦点与4.5:1文字对比度规则。主色由本次五版方案决定，未改原正式页规范。

## 实际交互

- 同一内存提供层：3个虚构账号、36个商品，每个类别12个；19位ID全程为字符串。原16列表头用于草稿核对，不增加业务字段。
- 选品历史采用琥珀徽章和日期。商品行操作为次按钮，草稿核对为主要操作；加入后可直接移除，保留按钮焦点，不弹确认窗。
- 软件识别包含找到一个、没有找到、多候选、旧信息失效四种情况；目录按钮仅选择虚构示例，候选须明确选择和保存，技术字段收进高级设置。
- 成果接入包含素材/成片、完整报告/无报告/报告冲突/归属歧义。无报告允许勾选人工核验后模拟接纳，冲突和错误归属不能接纳；正确指定任务后仍需人工核验。
- 组件样板覆盖主次按钮、禁用原因、字段错误、加载、空状态、失败、结果不明、独立人工核验以及紫色商家协同标记。
- 在线版只请求自身静态资源；离线版不请求任何额外资源。所有操作均不调用业务API、不访问公司路径、不写浏览器持久存储、不启动软件、不产生真实任务或下载表格。

## 本轮验收

HTTP浏览器检查13组通过，包含5主题×4视图×4尺寸共80种布局组合；20种主题/视图的正常文字与状态文字对比度至少4.5:1；每主题1440×1000首屏8行完整可见。检测到的业务API请求、外网请求、持久写入、页面错误及失败资源均为0。

覆盖主题切换保留账号/搜索/草稿、19位ID、历史直加、行添加/移除焦点、多候选保存、错误/正确归属、无报告人工核验、冲突阻止、16列弹窗关闭并恢复焦点及零下载。初次测试的空态定位与实际结构不同已修正；CSS过渡中间帧导致对比度采样不稳定，最终采用reduced-motion检查稳定颜色，并保留正常动效能力。真实截图已由主代理检查B/E选品视图。

测试脚本与本地证据：

- `tests/theme_preview_browser.test.mjs`；`test-results/theme-preview/report.json`及8张HTTP截图。
- `tests/theme_preview_offline_browser.test.mjs`；`test-results/theme-preview/offline-report.json`及离线截图。离线文件的5主题×4视图、历史直加通过；除主文档外额外资源、页面错误及持久写入均为0。

本地截图和报告不提交Git。此为虚构前端交互与视觉验收，不等于软件自动识别、外部文件核验或真实发布已经实现。

原Node单元31项通过，证据`test-results/single-machine/20261016-160957-281e96/summary.json`。离线测试会先自行导出HTML，不依赖已有dist产物；两个新测试文件均含browser命名，归入统一runner的浏览器组。
