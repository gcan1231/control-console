## 五套结构

| 方案 | 选品工作方式 | 软件识别 / 成果接入 |
|---|---|---|
| A 图片货架 | 暖白、顶部导航及横向账号、多列大图卡；底部草稿抽屉 | 来源与结果卡片并列，成果按任务卡核对 |
| B 表格批量 | 冷白靛蓝、窄侧导航、全宽紧凑表；勾选多件、批量加入、下方草稿 | 候选表及成果映射表逐行比较 |
| C 上下工作区 | 青灰深青、顶部导航、左账号；上方商品与下方草稿独立滚动，三种比例 | 上方控制、下方识别或匹配结果 |
| D 分步向导 | 米白深绿、账号→商品→草稿，单步集中操作 | 识别→候选→保存，或资料→匹配→人工核验 |
| E 快速检视 | 炭灰侧栏、左索引右单项详情，前后切换及底部草稿抽屉 | 左候选/任务列表右单项证据；保存对象明确显示，接纳前列出全部任务总览 |

选品由`theme-selection.js`分别返回五种结构；`theme-workflows.js`将候选和成果重组成卡片、表格、上下区、单步骤、主从检视。共享虚构提供层和语义控件，不以换颜色冒充布局变化。离线导出同时内联两个模块，无额外资源依赖。

## 设计依据与边界

继续应用本机ui-ux-pro-max、frontend-design、web-design-guidelines。设计系统查询出现营销页结果，未采用；收窄UX查询后采用表格内部横向滚动、批量选择、键盘焦点和对比度建议。在线核对[Vercel界面准则](https://github.com/vercel-labs/web-interface-guidelines)；使用系统中文字体，无远程字体或UI框架依赖。

设计语言学习自[Shadcn Admin](https://github.com/satnaing/shadcn-admin)、[Ant Design](https://github.com/ant-design/ant-design)、[Tabler](https://github.com/tabler/tabler)、[Fluent UI](https://github.com/microsoft/fluentui)、[Carbon](https://github.com/carbon-design-system/carbon)。五种工作方式为本项目自定义设计，不是这些项目的官方主题。

- 同一3个虚构账号、36个商品；19位ID保持字符串。草稿核对固定A:P16列，J仅记忆提示。
- 历史选品显示日期与醒目标记，可直接加入，不弹确认窗口。
- 软件识别覆盖找到、缺失、多候选、失效；目录仅虚构，不访问本机软件。E检视与选择分别表达，不保存未选中的当前详情。
- 素材/成片接入覆盖完整报告、无报告、冲突和歧义。无报告须人工核验，冲突及错误归属不得接纳。重新选表、目录或扫描清除旧歧义解法；换账号清除旧核验及批量勾选。
- 向导返回保留内容，自动跳步恢复到可见步骤焦点。C以选择器调比例，支持键盘。A/E草稿底部可达，展开内部滚动。
- 全部只保存页面内存，不调用业务API、不读公司路径、不写持久存储、不启动软件、不创建真实任务或下载表格。
