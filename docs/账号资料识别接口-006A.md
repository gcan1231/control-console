# 账号资料识别接口（006A）

状态：实现接口核对稿，2026-10-14；服务契约已按代码核实，浏览器与真实OCR能力另行验收。

账号资料严格保留A:H八列。B为字符串账号匹配键，D UID/E合作码保持文本；F限定食品/宠物、百货/个护家清、母婴，未知值人工映射；H公司编号可空、非空全局唯一。预览纠正后明确核对保存，未解决项留草稿。仅当前任务账号默认选中，其他不选；名称不同时保留来源名称与原任务名称，人工绑定且不改任务或目录。

本地Windows OCR处理截图；列坐标不可靠时先校准。多图/HTML/TSV的原始内容、抽取版本和修正确认版本均存本地ignored运行目录。

## 服务与HTTP
服务为 `AccountCaptureService(store, workbench)`；`preview(payload)`、`draft(captureId)`、`confirm(body)`、`list_drafts()`、`image(captureId)`。HTTP保持现有loopback、同源和token门禁：

| 方法与路径 | 输入/用途 |
|---|---|
| POST /api/account-captures/preview | 文本：kind=text、format=tsv/html、text；截图：kind=image、filename、content（base64）；重校准：captureId、options |
| GET /api/account-captures/draft?captureId= | 恢复最新抽取草稿，重新生成当前上下文revisionToken |
| GET /api/account-captures/image?captureId= | 读取通过摘要校验的原图快照 |
| POST /api/account-captures/confirm | 明确核对后保存所选行 |

preview/draft响应含captureId、revisionToken、kind、filename、rows、categoryOptions、warnings与截图尺寸/列边界。行对象用`fields`表示八列字符串，另有id、selected、saved、accountId、taskNames、currentProfile、allowed、issues、differences。`selected`仅提供默认勾选，不能替代保存确认。

confirm请求形状：`{confirmed:true,captures:[{captureId,revisionToken}],rows:[{captureId,rowId,fields,allowed,taskNames,verified:true}]}`。captures最多50个来源，rows为1—200行。每行allowed需从固定三类选择；taskNames必须是同B账号已有任务名称，有现存任务时须明确绑定。来源名称与执行名称分开保存。

revisionToken包含抽取版本、当前账号来源、任务上下文与已确认行；任务、账号资料或草稿变化会使旧确认请求失效。过期返回capture_stale；重复同账号候选不自动覆盖。H公司编号按大小写无关全局唯一，失败事务整体回滚。已保存行不能重复确认；未保存行继续留草稿。

补充资料中空白字段保留已有原字段（UID/H等），不会用空值清除已有资料。B/D/E拒绝科学计数法和控制字符；数值类型不接受，必须传字符串。确认后的原始八列、来源名称、执行名称绑定、固定类别及来源版本独立保留，不改原任务16列、ID或目录。

## 本地证据与截图校准
原内容和每次抽取版本存runtime/account-captures下；数据库另保留修正确认版本和审计。未确认预览不会生成已核对账号来源。截图上传单张12MiB以内；文本1MiB、最多500行。HTML只抽取单元格文字，不渲染外链或脚本；合并单元格拒绝猜测。TSV允许尾部G/H为空省略，抽取后仍补齐八列。

Windows OCR仅本地执行，坐标均为原图像素。options可传crop `{x,y,width,height}`、columns九条递增边界、rowBoundaries行边界。列检测需A:H锚点与连续网格线共同验证，不靠字母中点估算；证据不足返回零行草稿和校准提示；换行单元格建议显式行边界。OCR、列估算与文字跨边界警告不表示资料正确，必须逐项人工修正和核对。

## 检查限制
服务契约使用虚构文本与mock OCR坐标验证，不能据此宣称Windows OCR语言组件、真实截图识别准确率或真实账号资料已核验；浏览器覆盖见测试记录。
