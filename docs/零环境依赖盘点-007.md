审计日期：2026-10-16。范围：本仓库运行时源码静态审计；不连接真实账号或CDP端口，不启动发布，不修改产品文件或业务原件。当前计划仍为007。工作树中的便携启动器和依赖清单正在由主代理制作，本记录以本轮读取快照为准。

## 结论

公司电脑无需安装Python、Node.js、pip或npm是可行的，但必须交付完整便携目录，不能只复制源码或原有BAT。当前源码BAT会回退到PATH中的python，不满足正式交付要求。运行时不需要npm构建前端；Playwright自身包含Node驱动，该Node必须随包提供。已有账号Chrome及已打开的本机端口属于业务前置。

截图OCR另依赖Windows系统PowerShell、WinRT OCR及简体中文OCR语言组件。Pillow只负责图像验证/表格线处理，不能替代OCR引擎；系统没有中文OCR组件时，当前截图功能不能保证零安装可用。现有错误信息引导文本粘贴导入，可继续其他功能，但应明确说明这一截图能力限制；不能声称全部功能完全自包含。

## 路径、进程与外部连接风险

- 服务根由__file__计算；便携启动器默认data在包根。包必须解压到可写目录，不能在ZIP中运行；Program Files等无写权限目录需可理解提示。
- worker参数用列表传递，支持空格，但中文路径、嵌入式Python模块查找、DLL载入和PS1参数须实测。不能因列表参数正确而直接宣称便携通过。
- 启动器设置PLAYWRIGHT_NODEJS_PATH到包内node.exe，避免开发机环境重定向；worker继承环境。仅文件存在检查不足，须验证驱动实际启动和虚构worker执行。
- CDP探测为127.0.0.1显式端口，拒绝重定向并绕过代理；发布适配器还会访问真实平台网页。这些属于用户启动业务后的网络依赖，不属于首次联网安装依赖。本次未触发。
- OCR临时图保存在系统临时目录，结束后清理；TEMP目录权限、系统OCR最大图像尺寸、语言包和45秒超时均可能导致失败。
- 来源路径、成片路径及日志来源是在公司机重新配置的数据；不要把开发机绝对路径或数据库当作默认配置分发。

## 可行隔离验收

1. 在全新Windows x64虚拟机或Windows Sandbox中解压，确认没有Python/Node/pip/npm开发安装；记录OS版本、架构、OCR语言组件、浏览器版本。禁止外网或断网完成启动/依赖自检，记录网络与安装过程，不能以开发机清空PATH代替纯净机。
2. 分别在`C:\离线验收\总控制台 测试`和普通英文路径双击启动；由浏览器打开本地页面、访问各页，确认静态资源无外网请求、数据写入新目录。关闭/重启后虚构数据与日志保留；端口占用、目录只读、包文件缺失给出明确错误且不干预已有进程。
3. 仅使用虚构账号/商品/16列表、临时视频字节和隔离模拟适配器验证单账号独立worker；检查子进程exe为包内Python、驱动为包内Node、多个账号分离、失败及中断恢复不自动重提。不要绑定任何真实端口；如需浏览器协议集成，另用空白临时profile和本地夹具页面，不装载生产登录态。
4. 对系统中文OCR组件存在/不存在、PowerShell不可用、正常虚构截图分别验证成功或明确降级；没有组件的机器不能记为截图识别通过。测试不向在线表格写入。
5. 校验交付清单哈希和敏感内容排除，解压副本移动目录再启动；检查运行时没有pip/npm安装、下载浏览器或访问开发机路径。归档实际命令、退出码和截图，分别标注模拟通过、纯净机通过及真实业务未验。
